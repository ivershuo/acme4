# ACME4 项目整体修复与优化计划

日期：2026-09-12
状态：程序侧核心修复已实施并完成文档复核；生产 DNS 委派、真实 staging/production 签发、调度切换和生产指标接入仍待部署授权和实际凭据。

实施记录：配置、证书状态、版本化存储、部署恢复、结构化 hook、腾讯上传、通知节流、provider 凭据隔离、TLS 诊断和 release 门禁已经落地，并覆盖主要自动回归测试。磁盘满等依赖操作系统故障注入的场景、真实 DNS/CA/邮件链路和发布工作流的线上运行仍需在部署环境验收。第四阶段 K 的线上 DNS 修改及生产试点按本计划的授权边界未自动执行。

## 1. 范围与目标

本计划汇总整个项目 review 的问题，覆盖配置、账户、续签判断、DNS provider、证书存储、部署 hook、腾讯上传、通知、诊断工具和发布流程。

- 保留已确认的 Hurricane DNS 验证委派方案，作为独立实施阶段。
- **非 root 运行、sudoers、特权部署 helper、系统用户与 /etc 权限重构暂缓，不属于本计划。** 通用的落盘可靠性、hook 重试和部署状态仍需修复。
- 当前部署模型为单机定时执行；不引入多机协调或分布式锁。
- 保留现有配置和 hook 的兼容入口，不把 lego 大版本升级与本次修复绑定。
- 总体目标：失败可见、能够恢复；签发、保存和部署分别判断成功；配置与实际证书一致；DNS 验证减少对 HE 动态接口的依赖。

Review 基线：当时 `go test ./...` 和 `go vet ./...` 通过，但核心签发与部署失败路径缺少测试。生产故障日志尚未核对，因此代码问题不等于已证明的生产故障归因。

## 2. 分阶段实施

### 第一阶段：修复可能导致错误证书、文件损坏和假成功的问题（P1）

#### A. 配置与账户处理

问题：YAML 缺少语义校验；空 names 可越界；首域名相同的配置共用输出文件；账户密钥读取、解码、生成和写入错误被忽略，损坏 PEM 可导致 panic。

改动：
- 严格解析 YAML，拒绝未知字段；统一检查 names、provider、必要凭据、目录、解析器、时间参数及输出路径冲突。
- 域名规范化后用于比较；拒绝路径分隔符等不能作为合法域名的内容。重复证书项在外部请求前报错。
- 增加 `-check-config`，只读校验并给出配置项位置，不申请证书或执行 hook。
- 仅在账户密钥确实不存在时创建；逐项处理读取、PEM、密钥解析、生成、写入和关闭错误，不覆盖损坏的既有密钥。
- 账户目录使用 0700、私钥使用 0600，采用临时文件、同步和原子提交；持久化注册信息并按 CA 隔离。
- 先检查是否需要签发，再初始化 provider 与访问 CA；无需续签时仍可处理待部署任务和通知。
- 本轮保留旧相对路径相对工作目录的行为，生产示例改用绝对路径，避免悄悄改变已有配置含义。

验收：空 names、未知字段、重复路径、损坏账户文件和目录权限失败都返回明确错误；不 panic、不覆盖原密钥；全部证书有效且无待办时不访问签发 API。

#### B. 续签条件与证书完整性

问题：当前只检查证书到期时间；新增 SAN、私钥丢失或不匹配不会触发修复；所有证书读取错误都被当作文件不存在。

改动：
- 同时检查证书有效期、配置与证书的规范化 SAN 集合、私钥存在及匹配情况。
- SAN 新增或移除、证书损坏、私钥缺失或不匹配时进入重新签发流程；域名顺序变化不触发无意义签发。
- 区分不存在、内容损坏和权限/I/O 错误；权限与 I/O 错误直接报告，不盲目申请新证书。
- 默认继续提前 30 天续签，记录触发原因。

验收：新增泛域名、删除 SAN、密钥缺失、不匹配和证书读取失败均按对应原因处理；仅改变 SAN 顺序不重新签发。

#### C. 可靠保存与恢复

问题：两次 os.WriteFile 忽略错误并直接覆盖旧文件，可能留下半写入或不匹配文件，随后仍执行 hook 并报告成功。

改动：
- 每次签发写入独立版本目录；校验同一版本的证书、私钥与 SAN 后，同步文件并原子提交版本清单。
- 内部流程及 hook 占位符使用同一版本的明确路径，不分别解析可能变化的两个兼容入口。
- 保留旧 `<首域名>.crt/.key` 兼容路径，分别原子替换两个文件；部署状态指向不可变版本。明确独立读取两个兼容文件不能保证跨切换的成对快照，需要一致快照的 hook 使用同一版本路径。
- 保存失败不执行 hook、不发送续签成功通知，保留上一个完整版本。
- 保留当前、上一成功版本和仍待部署的版本；仅清理无引用旧版本，不删除待恢复数据。
- 状态文件也使用原子提交，支持在各提交点中断后恢复。

验收：注入磁盘满、第二个文件写入失败、指针提交失败及进程中断；旧版本可用，恢复后不会把未完整保存的版本标为成功。

#### D. 部署状态和独立重试

问题：hook 失败只形成摘要，主流程仍成功；下一轮因为本地证书有效而跳过部署，线上可能持续使用旧证书。

改动：
- 以证书版本和 hook 标识持久化每一步状态，区分已保存、待部署、部分部署成功和全部部署成功。
- 新一轮优先处理有效的待部署版本，只重试失败或未完成的步骤，不重复签发、不重复执行已确认成功的步骤。
- hook 配置变化时按新配置标识重新判断需要运行的步骤；旧字符串 hook 使用内容及出现位置生成稳定标识，结构化 hook 使用显式 id。
- 待部署版本在进入 hook 流程前已经持久化；每个 hook 成功后记录结果，不在每次执行前重复写入未变化状态。进程中断后的外部操作只能保证至少一次，因此文档要求 hook 可安全重跑，不宣称任意命令恰好执行一次。
- 统一汇总签发、保存、部署结果，任何必要步骤失败均以非零码结束；一个证书失败不阻止其余证书处理。
- 只有保存和全部必要 hook 完成才报告整体成功；没有 hook 时明确报告证书保存成功。

验收：第一次签发成功、上传或 reload 失败；第二次只重试对应 hook，无 ACME 请求；部分成功、配置变化和中断后恢复均可验证。

### 第二阶段：消除阻塞并修复 hook、上传工具（P1/P2）

#### E. hook 执行与凭据

- 增加结构化 `hooks`：id、command、args、timeout、env_file；与原 `post_renew_hooks` 二选一，避免重复执行。旧字符串配置继续使用原 shell 语义。
- 结构化参数逐个替换占位符，直接执行参数数组，路径空格和特殊字符不再经 shell 重新解释。
- 旧 shell 模式保留兼容并给出迁移说明，不尝试用自动加引号改变已有模板。
- 默认 hook 超时 120 秒，Linux 超时或取消时终止整个进程组；输出最多保留 64 KiB，并标明截断。
- 日志只展示 hook 标识、结果和已脱敏信息，不输出含凭据的完整命令。环境文件不执行 shell，限制读取权限。
- 结构化 hook 使用基础运行环境加其显式环境配置，避免继承无关 DNS/邮件密钥；旧模式保留兼容，文档说明区别。

验收：空格路径、引号、特殊字符、未知占位符、超时子进程、超量输出及凭据脱敏；旧示例中合法 shell 用法保持兼容。

#### F. 腾讯证书上传

- 修复 README 与 config.sample.yaml 的互斥参数示例：使用 `--cert`、`--key`、`--alias`，不同时传 `--domain`。
- 推荐通过独立环境配置传递腾讯凭据，不在示例中将 SecretKey 放进进程参数；现有参数暂时保留兼容并标注不推荐。
- 使用 `Repeatable:false`，正确接受 `CertificateId` 或 `RepeatCertId`，重复上传返回既有 ID。
- 上传工具继续校验证书和私钥匹配，增加明确请求超时；上传成功只表示进入腾讯证书服务，不表示已经绑定到 CDN、CLB 等线上资源。

验收：直接将文档示例参数交给解析器；覆盖首次上传、只有 RepeatCertId、空 ID、API 错误、请求超时和密钥不匹配。

### 第三阶段：通知、凭据隔离与诊断（P2）

#### G. 通知覆盖、超时与去重

- 邮件使用有 15 秒总超时的 HTTP client 或 context；发送失败继续处理其余证书。
- 在统一结果出口处理通知，覆盖 provider 初始化、账户注册、签发、保存和部署失败，避免同一错误多处发送。
- 配置尚无法解析或通知参数不可用时，明确输出日志和非零退出码，不承诺此类错误能够通过该配置发送邮件。
- 将通知状态与签发状态分开，通知失败不得触发重新签发；待通知事件在后续运行重试。
- 按证书指纹、事件类型及阈值持久化去重；成功确认后记录已发送，历史记录约 400 天后清理。响应丢失等不确定场景不能宣称严格恰好一次。
- 保留续签窗口前 7、3、1 天提醒；增加实际到期前 7、3、1 天及过期提醒，独立于续签分支执行。
- 按跨越阈值触发，漏跑后只补最高紧迫等级，避免错过单日窗口或集中补发多封。
- 同类持续失败默认每天最多提醒一次；首次失败、错误类别变化、临期升级与恢复立即提醒。

验收：每 6 小时运行不重复发送已确认的同一阈值提醒；续签持续失败仍有临期告警；邮件超时、发送失败和跨进程重启行为可验证。

#### H. provider 与日志

- Cloudflare、Hurricane、TencentCloud（DNSPod）、Porkbun 直接传 provider 配置，不再通过 os.Setenv 传凭据。
- 保留旧内联 credentials，新增同键名的 credentials_file 引用；同一 provider 不允许同时配置两种来源，文件内容严格解析且不输出到错误日志。独立凭据文件强制限制 group/other 权限；内联凭据所在主配置的权限暂由部署者按文档设置为 0600，程序不强制拒绝以保持兼容。
- 继续保留 logging wrapper 的 Timeout、Sequential 等能力委托；使用 EffectiveFQDN 显示实际委派目标，自动 provider 不再无条件打印成“请手动添加”。
- 增加运行编号、证书标识、阶段、耗时、错误类别和待重试状态；provider 长期凭据和结构化 hook 的 env_file 值不进入日志。旧字符串 hook 仍有泄露展开参数的兼容风险，文档要求不在参数中放凭据。

验收：不同 provider 实例并发初始化时凭据不串用；包装器不丢失可选能力；CNAME 场景日志显示实际目标；日志不含凭据。

#### I. 远程证书诊断

- 将连接地址、端口和 SNI 分离，使用标准 host/port 解析处理域名、IPv4、裸 IPv6 和带括号 IPv6。
- 默认端口 443；带端口域名不能把端口写入 SNI；IP 输入不发送错误的域名 SNI。
- 保留读取不受信/过期证书用于诊断的能力，同时分别显示证书链信任、主机名匹配和有效期状态，不把握手成功描述成验证成功。

验收：域名默认端口、自定义端口、IPv4、IPv6、多 SNI 虚拟主机以及不受信和过期证书。

### 第四阶段：DNS 可靠性与 Hurricane 委派迁移

现有公开资料尚未提供 HE 新接口已解决动态 TXT 限制的证据。业务 DNS 留在 HE，验证 TXT 转移到独立 Cloudflare 域名，是已确认的长期方案。

#### J. 程序侧 DNS 修复

- 通过 `dns01.AddRecursiveNameservers` 真正应用 dns_resolvers；正确处理地址与端口，保留权威 DNS 传播检查，不用关闭检查掩盖故障。
- 保留 HE 顺序验证、传播超时和有界 interval 退避。兼容 `:` 与既有文档的 `=` token 格式；完整记录 token 优先于域名 token。
- 修正文档、限流诊断和测试，明确锁/限流器的实例范围以及清理写入 `.` 的行为。迁移后不再调用 HE 动态 TXT API；本期不重写 HE 为多值 DNS 服务。
- 对读取到的清理错误保留独立警告，不覆盖原始签发错误；测试多 TXT 的清理只影响本次记录。
- 新增 acme_directory_url，staging 与生产使用独立账户、证书、状态及 hook 配置。

#### K. 委派迁移步骤

1. 准备专用验证域名并托管到 Cloudflare，配置仅限此 zone 的 DNS Write 和 Zone Read token；可使用一个组合 token，也可用 `api_token` 与 `zone_api_token` 拆分权限。
2. 为每个不同 challenge 主机名分配唯一目标，记录映射表；根域名及对应泛域名共享目标。
3. 核查实际生产失败日志和定时任务，建立迁移前基线；备份 HE 动态 TXT 和现有有效证书。
4. 试点一组根域名与泛域名：暂停该组签发，将 HE 同名 TXT 替换为 CNAME，等待旧 TTL 与相关缓存过期。
5. names 不变，provider 改为 cloudflare，依靠 lego 的 CNAME 跟随向目标写 TXT。
6. 在独立 staging 环境验证真实 challenge；重复验收需避免授权缓存掩盖 DNS 流程，禁止执行生产 hook。
7. 生产试点通过后逐组迁移；回退需恢复 HE 动态记录及必要 token、恢复配置并等待传播，期间继续使用旧有效证书。

验收：CNAME 链有效；root/wildcard 两份 TXT 共存且精确清理；错误目标、缺失 CNAME、权限不足及传播超时都能定位；迁移组不请求 HE 更新接口。

### 第五阶段：调度、测试、发布与维护

#### L. 单机运行与调度

- 在任何账户或证书写入前获取账户目录下的操作系统文件锁，覆盖整个处理流程；锁被占用明确退出，进程退出后自动释放。
- 单机 cron 和人工执行统一使用同一账户目录；不声称此锁覆盖不同目录或多台机器。
- 超时、防重入和通知去重完成后，cron 改为每 6 小时检查。提供绝对路径、明确工作目录和日志轮转的示例。
- 不添加整单无界重试；短期错误留到下一轮。当前有效的待部署版本优先重试，新签发成功后再替换被淘汰的待部署版本。

#### M. 结构与 CI

- 将 main.go 收敛为参数与调度入口；拆分配置/账户、证书状态与存储、签发、hook、通知结果汇总，便于注入 fake provider、CA、时钟和文件操作。
- 主流程返回结果及错误，由入口统一决定退出码；主程序底层流程不散落 os.Exit 或重复通知。独立的腾讯上传命令仍在自身入口根据参数/上传结果退出。
- PR 检查和 release 前运行 `go test ./...`、`go vet ./...`，对共享状态及锁相关测试运行 race 检查。
- Go 版本从 go.mod 读取，消除 release 中 Go 1.22 与项目声明不一致的问题；不依赖隐式工具链下载掩盖配置差异。
- 发布主程序与腾讯上传工具，生成校验和，并确保测试通过后才发布。非 root helper 不在本轮产物中。
- 同步 README、通知指南、配置样例与 hook 文档；把示例参数组合纳入测试，防止文档与实现再次矛盾。

验收：故意引入测试失败时 release 不执行；发布产物可启动；样例通过配置和参数解析；所需失败路径不依赖真实 DNS、CA 或邮件服务。

## 3. 总体验收与交付

- 第一阶段完成后，新增 SAN、丢失私钥、写入失败、hook 失败不会再被误报为完整成功。
- 部署失败后再次执行只重试必要部署步骤；程序中断后能从持久化状态恢复。
- 网络或子进程卡住不会无限阻塞整批证书；任一证书失败不影响后续证书尝试，最终状态准确。
- 每 6 小时调度不会因重叠执行覆盖 DNS/账户/证书，也不会重复发送已确认的同一提醒。
- 委派迁移后的真实 DNS challenge、签发、保存和 hook 闭环通过试点，才逐组上线。
- 交付包括代码、回归测试、配置迁移说明、cron 示例、发布工作流与回退步骤；实际 release 产物由打 tag 后的 CI 生成。
- 单独统计签发成功率、部署成功率、传播耗时、待部署数量、清理警告与剩余有效期；不承诺外部 DNS/CA 永不故障。

执行时简单模块和测试可由 5.6-luna/5.6-sol 子 agent 分工；证书版本提交、恢复逻辑与状态汇总统一复核。本计划不授权注册域名、修改线上 DNS 或执行生产部署；这些步骤在代码与迁移清单可审阅后进行。
